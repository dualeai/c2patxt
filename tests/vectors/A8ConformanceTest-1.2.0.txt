# Date: 2026-08-06
# C2PA Technical Specification 2.4 (2026-04-01), HTML build c7e55d5a,
# Annex A.8 "Embedding Manifests into Unstructured Text".
#
# Conformance vectors for the C2PATextManifestWrapper wire format. This file is the
# normative artefact; any JSON mirror is generated from it and must agree.
#
# FORMAT
#   Columns are separated by semicolons:
#     id; op; text_hex; payload_hex; expect_hex; status; flags
#   Trailing '#' introduces an informative comment. Text after '#' is never data.
#   Blank lines and lines whose first non-space character is '#' are ignored.
#   Section markers begin '@Part' and run to the first space or '#' -- '@Part1',
#   '@Part2b'. They carry no data.
#
#   ALL DATA IS US-ASCII, and every byte-bearing field is lowercase hex. 'text_hex'
#   and an embed record's 'expect_hex' decode as UTF-8 text; 'payload_hex' and an
#   extract record's 'expect_hex' are OPAQUE MANIFEST BYTES and need not.
#   There are no \uXXXX escapes, no base64, no literal non-ASCII characters, and
#   this file carries no byte-order mark. That is deliberate: the subject matter is
#   invisible characters, and a file containing them literally would be mangled by
#   editors, terminals, diff viewers and review tools. The Unicode Character
#   Database applies the same discipline -- NormalizationTest.txt has zero non-ASCII
#   bytes before the '#' on any of its 20,034 data lines.
#
# CONFORMANCE
#
# 1. WIRE FORMAT (A.8.2.2, A.8.3.1, A.8.4.1). The wrapper body is
#      magic(8) || version(1) || manifestLength(4) || jumbfContainer[manifestLength]
#    magic == 0x4332504154585400 ("C2PATXT\0"); version == 1;
#    manifestLength is a BIG-ENDIAN unsigned 32-bit integer.        [see note 1]
#    Each body byte b maps to a code point:
#      0x00 <= b <= 0x0F  ->  U+FE00 + b
#      0x10 <= b <= 0xFF  ->  U+E0100 + (b - 16)
#    The body is prefixed by exactly one U+FEFF and forms one contiguous run.
#
# 2. EMBED. For every record with op=embed and status=OK:
#      embed(text_hex, payload_hex) == expect_hex
#    and the wrapper appears as one contiguous run at the END of the text.
#
#    NOTE THE ARITY: this op is the WIRE-LEVEL primitive -- given text and an opaque
#    manifest payload, append the wrapper. It is NOT any particular SDK's public
#    embed() function, which will take a signing key and a disclosure and will
#    legitimately do more: choose the exclusion offsets, build and sign the manifest,
#    and NORMALIZE the visible text before marking. This file says nothing about
#    those steps; it pins the bytes of the wrapper alone. A record whose text_hex is
#    not NFC therefore describes the primitive faithfully and does NOT assert that a
#    conforming producer leaves the caller's text un-normalized.
#
# 3. EXTRACT. For every record with op=extract and status=OK:
#      extract(text_hex) == (expect_hex, OK)
#
# 4. FAILURE. For op=extract with a status naming a C2PA failure code, an
#    implementation shall report exactly that code, shall return no manifest, shall
#    not raise an unhandled error, and shall not consume unbounded time or memory.
#
# 5. ABSENCE IS NOT FAILURE. For op=extract with status=NONE, extract(text_hex)
#    returns no manifest and reports no failure code. Unmarked text is the normal
#    case and is not an error.
#
# 6. ROUND TRIP. For every op=embed record with status=OK,
#      extract(expect_hex) == (payload_hex, OK)
#
# 7. WRAPPER EXTENT. A wrapper ends at 13 + manifestLength decoded bytes, never at
#    the end of the contiguous selector run. Variation selectors authored by the
#    user immediately after a wrapper are not part of it.
#    Records X0017 and X0018 cover this. It is the rule
#    encypherai/c2pa-conformance-suite gets wrong -- it takes a wrapper's end as the
#    start of the next wrapper or EOF -- so it is the discriminating case.
#
#    On rule 4's cost clause: records X0019 and X0020 carry inputs SHAPED to be
#    expensive rather than large enough to be slow, because a text file cannot carry
#    a multi-megabyte input and wall-clock time is not portably assertable. X0019 is
#    16 magic-matching but malformed candidates; REPEAT THE 34-BYTE UNIT to whatever
#    length your harness needs, and confirm the time grows linearly, not
#    quadratically. A real implementation was quadratic here -- it re-encoded the
#    whole document once per candidate, so 1.09 MB took 9.91 s.
#
# 8. CLOSED WORLD. For any text T containing no U+FEFF followed by a
#    magic-matching variation-selector run, extract(T) == (none, NONE).
#
# 9. A CORRUPT CANDIDATE SHALL NOT DISCARD A GENUINE WRAPPER. Rule 4 says a
#    magic-matching malformed candidate reports corruptedWrapper, and rule 1's
#    hazard notes say a non-matching run is skipped. Neither says what to do when
#    BOTH appear in one text. Report the failure only if no valid wrapper was
#    found; otherwise return the valid one. The alternative hands a denial of
#    service to anyone able to prepend twenty characters to a document. X0021 is
#    the discriminating record: an implementation that raises on the first corrupt
#    candidate and one that returns the wrapper pass every other record alike.
#
# Note 1: A.8.2.2 declares manifestLength in ISO-BMFF class syntax and the prose
#    never states endianness -- the only place in the specification that omits it,
#    where clause 11, clause 18.6 and A.3.x all state it explicitly. Big-endian is
#    confirmed three ways: by decoding EncypherAI's published golden vector, by
#    re-deriving writerslogic's vector from the formula above, and by both
#    implementations' source (struct.Struct("!8sBI"); len.to_be_bytes()).
#    Record E0001 below reproduces EncypherAI's "ascii_small" vector byte for byte.
#
# FLAGS
#   ascii        input text is pure ASCII
#   minimal      smallest meaningful case
#   roundtrip    extract of a known-good embed
#   truncated    wrapper is cut short of its declared manifestLength
#   duplicate    more than one valid wrapper present
#   no-wrapper   no wrapper present at all
#   combining      input contains combining marks
#   astral         input contains supplementary-plane (non-BMP) code points
#   nfd-input      input is NOT in NFC; embed must not normalize it
#   cjk            input contains CJK characters
#   rtl            input contains right-to-left script
#   emoji-vs       text carries legitimate variation selectors of its own
#   all-bytes      payload exercises every byte value 0x00-0xFF
#   stray-marker   a U+FEFF with no selector run after it
#   bad-magic      a selector run that does not decode to the magic
#   short-run      selector run shorter than the structure requires
#   bom            input begins with a UTF-8 byte-order mark
#   empty          empty input
#   whitespace     whitespace-only input
#   garbage-prefix a magic-looking run precedes a genuine wrapper
#   bad-version    wrapper version field is not 1
#   length-overrun declared manifestLength exceeds the bytes available
#   trailing-vs    user variation selectors follow the wrapper and are not part of it
#   pathological   input shaped to cost a naive implementation more than it should
#   corrupt-prefix a magic-MATCHING but malformed candidate precedes a genuine wrapper
#   empty-manifest declared manifestLength is 0: well formed, carrying no manifest
#   boundary       payload straddles the 0x0F/0x10 mapping boundary on extract
#
